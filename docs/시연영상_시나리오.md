## 촬영 전 준비

**1. 실행 중인 앱 종료** — 백그라운드로 떠 있으면 `Ctrl+C`가 듣지 않습니다.

```bash
powershell -Command "Get-NetTCPConnection -LocalPort 8080 -State Listen | Select-Object -First 1 -ExpandProperty OwningProcess | ForEach-Object { Stop-Process -Id $_ -Force }"
```

**2. 컨테이너 전부 내리기** — 기동 장면을 찍어야 하므로

```bash
docker compose down
```

**3. 네이티브 Ollama는 켜둔 채로** — 영상에서 띄우지 않습니다

```bash
curl http://localhost:11434/api/tags
```

두 모델(`gemma4:e2b`, `bge-m3`)이 보이면 정상.

**4. 나머지**
- `dataset/` 폴더에 데이터셋이 있는지 확인
- 브라우저 탭에 `http://localhost:8080` 미리 입력해 두기 (아직 오류가 나는 게 정상)
- 터미널 글자 크기 16pt 이상, 불필요한 창 닫기

**녹화 시작**: `Win + Alt + R`

## 타임라인

### 1. 도입 — 터미널 (0:00 ~ 0:10)

> 화면: 프로젝트 디렉터리가 열린 빈 터미널

> 지정과제, MCP 기반 지능형 데이터 플랫폼입니다.
> 일상어로 질문하면 규칙 기반 라우터가 도구를 고르고, PostgreSQL을 조회한 결과를
> 로컬 LLM이 문장으로 정리합니다. 외부 API는 쓰지 않습니다.

---

### 2. 컨테이너 기동 (0:10 ~ 0:22)

```bash
docker compose up -d postgres
```

> pgvector를 얹은 PostgreSQL을 올립니다.
> 컨테이너가 뜨면서 초기화 스크립트가 스키마와 데이터를 적재합니다.
> Ollama는 GPU 가속을 위해 호스트에 네이티브로 설치했습니다.

```bash
docker compose ps
```

> healthy를 확인하고 애플리케이션을 띄웁니다.

---

### 3. 애플리케이션 기동 (0:22 ~ 0:34)

```bash
./mvnw spring-boot:run
```

> 애플리케이션과 함께 MCP 서버가 기동됩니다.
> 로그의 **`Registered tools: 3`** — 과제가 요구한 도구 세 개가 등록됐습니다.
> 기동 시 문서 40건 임베딩과 그래프 적재도 자동 수행됩니다.

**확인 포인트** — `Registered tools: 3` 줄을 화면에 잠시 보여줍니다.

---

### 4. 시연 ① 문서 검색 (0:34 ~ 0:54)

> 화면 전환: 브라우저 새로고침

> 상단이 과제의 6단계 흐름입니다.

**조작** — 칩 `백업 정책은 어떻게 되어 있어?` 클릭

> 첫 질문은 모델 적재 시간이 포함됩니다.

*(약 8초 대기 후 결과)*

> `vector_search`가 선택됐습니다. 점수는 9 대 0 대 0.
> 문서 키워드가 누적돼 다른 도구를 압도했습니다.
> **이 점수가 판단 근거입니다.**
> 답변은 Product-S1 26일, Product-C4 90일 보관.
> 문서 40건 중 3건만 추려 그 근거로 답했습니다.

---

### 5. 시연 ② 관계 탐색 (0:54 ~ 1:09)

**조작** — 칩 `Client-A가 사용 중인 제품 목록은?` 클릭 *(0.8초)*

> 이번엔 `knowledge_graph`. 점수 분포가 완전히 다릅니다.
> **주목할 부분은 인자입니다.** 라우터가 개체명 `Client-A`와 관계 `USES`를 직접 뽑아냈습니다.
> 도구 이름만이 아니라 호출 인자까지 규칙이 만듭니다.
> 답은 Product-C3와 Product-S1. 재귀 CTE 탐색이라 1초 안에 끝났습니다.

---

### 6. 시연 ③ 자연어 → SQL (1:09 ~ 1:29)

**조작** — 칩 `2025년 3분기 총 매출액은 얼마야?` 클릭

> 세 번째는 자연어를 SQL로 바꾸는 도구입니다.
> 이것만 LLM을 두 번 탑니다. SQL을 만들 때, 결과를 문장으로 만들 때.

*(약 7초 후 결과 — **원본 근거 펼치기**)*

> 답은 23,859. 펼치면 **실제 실행된 SQL이 그대로** 들어 있습니다.
> 검증할 수 있어야 하므로 항상 함께 반환합니다.
> LLM이 만든 SQL은 조회문 외 차단, 읽기 전용 트랜잭션, 실행 시간 제한으로 3중 검증합니다.

---

### 7. 차별점 (1:29 ~ 1:51)

> 화면: 시연 페이지 그대로

> 핵심은 규칙과 소형 LLM의 역할을 **측정으로 나눈 것**입니다.
>
> 42개 질문으로 비교했습니다.
> 규칙만 38점, LLM만 34점, **둘을 협업시키면 40점.**
>
> 규칙은 도메인 어휘에 강하고 LLM은 표현 변화에 강합니다.
> 그래서 규칙이 확신할 때만 규칙을 쓰고, 확신 못 하는 질문만 LLM에게 넘깁니다.
>
> 추론 옵션도 작업마다 갈렸습니다. SQL 생성은 켜야 정확하고,
> 답변 생성은 꺼야 세 배 빠르면서 더 구체적이었습니다.

---
